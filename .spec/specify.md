# Specify: mcp-mail-manager

> 本ドキュメントは、このプロジェクトで構築するシステムの全体像（上位ビジョン）を示す。
> 詳細な要件は requirements.md、技術判断は design.md に委ねる。

## 1. 一言で言うと

AI エージェント（Claude Code / Claude Desktop など MCP クライアント）が、個人の IMAP / SMTP メールボックスを検索・閲覧・送信・返信・整理・予約送信できるようにする、AWS 上でホストするリモート MCP サーバ。受信メールは IMAP から定期同期して S3（本文）と DynamoDB（メタ情報）に保管し、検索は DynamoDB で行う。

## 2. 解決する課題

- AI エージェントから自分のメールを扱う標準的な手段がなく、メールの検索・要約・返信を人手で往復している。
- 特定ベンダ（Gmail API / Graph API）向けの連携は存在するが、自前サーバやプロバイダを問わない IMAP / SMTP 汎用の連携手段が欲しい。
- 「指定日時に送る」といった、クライアントを閉じた後も動く処理はローカルの MCP プロセスでは実現できない。
- メールサーバの認証情報（IMAP / SMTP パスワード）を LLM のコンテキストに載せずに操作させたい。

## 3. 利用者 (Actors)

| Actor | 誰か | 何をしたいか |
|-------|------|--------------|
| 開発者（オーナー） | この MCP をデプロイし、自分のメールアカウント 1 つを接続する個人 | Claude 等から自然言語でメール業務（検索・要約・返信・整理・予約送信）を頼みたい |
| AI エージェント | 開発者が使う MCP クライアント（Claude Code / Claude Desktop 等） | MCP ツール経由でメールボックスを操作する。認証情報は知らない |
| スケジューラ | AWS 側の時刻起動コンポーネント | 予約されたメールを指定時刻に確実に 1 回だけ送信する |
| 同期ジョブ | AWS 側の定期実行コンポーネント | IMAP から新着メールを取り込み、本文を S3、メタ情報を DynamoDB に保管する |

## 4. スコープ

### やること (In scope)

- IMAP / SMTP 汎用プロトコルによるメールサーバ接続（1 ユーザ・1 メールアカウント）
- Streamable HTTP トランスポートのリモート MCP サーバを AWS 上にサーバレスで提供する
- 受信メールの定期同期: IMAP から取り込み、本文（生メッセージ）を S3、メタ情報（件名・差出人・日時・フォルダ・既読等）を DynamoDB に保管する
- 受信メールの検索・一覧・本文閲覧。検索は DynamoDB のメタ情報に対して行う（添付はファイル名・サイズ等のメタ情報のみ）
- 新規メールの送信（プレーンテキスト）
- 既存メールへの返信（スレッド維持）・転送
- メールの整理: 既読 / 未読、フォルダ移動、削除、フラグ
- 予約送信: 1 通を指定日時にサーバ側で送信する。予約の一覧・取消を含む
- メールサーバ認証情報の AWS マネージドサービスでの保管と、MCP クライアントの認証
- IaC（AWS CDK）によるデプロイと、develop → dev → main → prod の CI/CD

### やらないこと (Out of scope)

- 複数ユーザ・複数メールアカウントの対応（初版は 1 ユーザ 1 アカウント）
- Web UI / 管理画面（設定は IaC と Secrets Manager で行う）
- 添付ファイルの取得・送信（後続フェーズ）
- Gmail API / Microsoft Graph API 等のベンダ固有 API 連携
- 複数宛先への一斉送信（メルマガ的用途）
- HTML メールの作成（送信はプレーンテキストのみ）
- メールの完全削除（EXPUNGE）

## 5. 成功の定義

- Claude Code / Claude Desktop に MCP を登録し、自然言語で「先週の A さんからのメールを要約して返信して」が完了する。
- 予約したメールが、クライアントを閉じていても指定時刻に送信され、二重送信されない。
- IMAP / SMTP の認証情報がツールの入出力・ログ・LLM コンテキストに一切現れない。
- 利用しない月の AWS 月額がほぼゼロ（数ドル以内）に収まる。

## 6. 制約・前提

- 憲法由来: AWS 前提（`ap-northeast-1`）、IaC は AWS CDK、サーバレス優先（Lambda / DynamoDB / EventBridge）、TDD（Red → Green → Refactor）。
- 憲法由来: `develop` への push で dev へ自動デプロイし、正常性テスト通過後に `main` へ昇格する。
- メールサーバは IMAP（受信・整理）と SMTP（送信）を提供し、パスワード認証（または App Password）で接続できること。
- 予約送信の実行時刻は AWS 側の時刻起動コンポーネントに依存するため、分単位の精度を前提とする。
- 検索・閲覧は同期済みデータに対して行うため、新着メールが見えるまでに同期間隔分の遅延がある。整理操作は IMAP に反映し、同期データにも反映する。

## 7. 用語集

| 用語 | 定義 |
|------|------|
| MCP | Model Context Protocol。AI エージェントが外部ツールを呼び出すための標準プロトコル |
| Streamable HTTP | MCP のリモートトランスポート。HTTP POST / SSE で JSON-RPC をやり取りする |
| IMAP | 受信メールの閲覧・検索・整理を行うプロトコル |
| SMTP | メールを送信するプロトコル |
| 予約送信 | エージェントが作成した 1 通を AWS 側に保存し、指定日時にスケジューラが送信すること |
| 整理操作 | 既読 / 未読、フォルダ移動、ゴミ箱への移動、フラグ付与などメールの状態を変える操作。完全削除（EXPUNGE）は行わない |
| 同期 | IMAP メールボックスの内容を S3 / DynamoDB に取り込むこと。一方向（IMAP → AWS）を基本とし、整理操作は IMAP と AWS の両方に書く |

## 8. 決定済み事項

- メール本体は S3、メタ情報は DynamoDB に保管し、検索は DynamoDB で行う（IMAP SEARCH には依存しない）。
- 送信メールはプレーンテキストのみ。受信 HTML メールはテキスト化して返す。
- 削除は「ゴミ箱へ移動」のみ。完全削除は行わない。
