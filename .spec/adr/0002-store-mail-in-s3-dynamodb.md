# ADR-0002: 受信メールを IMAP から定期同期し S3 + DynamoDB に保管する

- **日付**: 2026-09-19
- **ステータス**: Proposed
- **関連要件**: REQ-001〜004, REQ-010, REQ-011, NFR-001, NFR-002
- **関連憲法条項**: 2. サーバレス優先（データ: DynamoDB 優先）

## 文脈 (Context)

検索・閲覧を毎回 IMAP に問い合わせる方式（パススルー）と、AWS 側に取り込んで検索する方式がある。
パススルーは保存コストがゼロだが、IMAP SEARCH はサーバ実装依存で遅く、ツール呼出ごとに IMAP 接続（TLS ハンドシェイク + LOGIN）が必要で応答が遅い。さくらのメールサーバ（Courier IMAP）は全文検索拡張を持たない。
ユーザは「受信は IMAP で定期的に行い S3 に保存、メタ情報を DynamoDB に保管し検索も DynamoDB で行う」方式を選択した。

## 決定 (Decision)

EventBridge Scheduler（15 分間隔）で起動する同期 Lambda が IMAP の全フォルダを差分取得し、生メッセージを S3、メタ情報を DynamoDB（単一テーブル）に保存する。検索ツールは DynamoDB のみを参照し、閲覧ツールは S3 の生メッセージを解析する。整理操作は IMAP を先に更新し、成功後に DynamoDB を更新する。保持期間は 1 年（S3 ライフサイクル + DynamoDB TTL）。

## 検討した選択肢

| 選択肢 | 利点 | 欠点 | コスト影響 |
|--------|------|------|------------|
| A: S3 + DynamoDB に同期（採用） | 検索が速く IMAP 実装に依存しない。検索ツールが IMAP 接続不要で応答 2 秒以内を満たしやすい | 新着反映に最大 15 分の遅延。同期・整合性のコードが必要。保存データの管理責任 | S3 約 2 GB / 年 + DynamoDB オンデマンド: 合計 0.5 USD / 月未満 |
| B: IMAP パススルー | 実装が少なく常に最新 | IMAP SEARCH の性能・機能がサーバ依存。ツールごとに接続確立で 1〜3 秒の遅延 | 0 USD |
| C: OpenSearch Serverless で全文検索 | 本文検索が可能 | 最低料金が高く NFR-001 に反する | 約 700 USD / 月 |

## 結果 (Consequences)

- 良い点: 検索が DynamoDB Query で完結し、IMAP サーバの負荷と制限（接続数）を気にしなくてよい。
- 悪い点 / トレードオフ: 新着の反映遅延。整理操作の二重書込による不整合リスクは「IMAP 成功後に DynamoDB 更新 + 次回同期で再調整」で抑える。
- 憲法との関係: 準拠（DynamoDB / S3 / Lambda / EventBridge のみ）。
