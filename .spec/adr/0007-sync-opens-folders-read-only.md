# ADR-0007: 同期ジョブは IMAP フォルダを読み取り専用（EXAMINE）で開く

- **日付**: 2026-10-31
- **ステータス**: Accepted
- **関連要件**: REQ-005, REQ-001, REQ-003
- **関連憲法条項**: 4. 最小の変更

## 文脈 (Context)

同じさくらのメールボックスを、別のシステムが POP3 で受信している。そのシステムは本システムの管理外で、受信後もサーバにメールを残す設定にしている。POP 側が受信済みを何で判断しているかは分からない。通常は UIDL だが、サーバの新着状態に依存している可能性もある。ユーザは予防として、同期ジョブが POP 側に干渉しない構成を求めた（取りこぼしはまだ起きていない）。

これまでの同期ジョブは、本文を `BODY.PEEK[]` で取得していたので既読（`\Seen`）は付けていない。一方、フォルダは `SELECT`（読み書き）で開いていた。RFC 3501 の規定により、読み書きで開いた接続はそのフォルダの全メッセージの新着状態（`\Recent`）を消費する。以降の接続からは新着に見えなくなる。Courier-IMAP は Maildir の `new/` から `cur/` へのファイル移動で新着状態を表すので、`SELECT` はサーバ上のファイル配置も変える。dev と prod の同期ジョブはどちらも同じメールボックスを 15 分ごとに開いている。

## 決定 (Decision)

同期ジョブが使う IMAP セッションは、すべてのフォルダを `EXAMINE`（imapflow の `mailboxOpen(path, { readOnly: true })`）で開く。`ImapSessionFactory` に `{ readOnly }` を追加し、`runSync` が `readOnly: true` を指定してセッションを開く。MCP ツールと scheduled-send は従来どおり `SELECT` を使う。

## 検討した選択肢

| 選択肢 | 利点 | 欠点 | コスト影響 |
|--------|------|------|------------|
| A: 同期ジョブだけ `EXAMINE` で開く（採用） | RFC 3501 で「`EXAMINE` は新着状態を含むメールボックスの状態を変えてはならない」と規定されている。同期ジョブはフラグを読むだけで書かないので、機能を落とさずに切り替えられる。変更はセッションを開く 1 か所 | 新着状態が実際に保たれるかは、サーバの実装（Courier）に依存する。公開情報では確認できず、実機確認が必要 | 0 |
| B: 現状維持（`SELECT` + `BODY.PEEK[]`） | 変更なし | 既読は守れるが、新着状態は消費する。POP 側が新着状態に依存していれば干渉する | 0 |
| C: INBOX を POP3（UIDL 差分）で取り込む | IMAP の新着状態に一切触れない | POP3 は接続中にメールボックスをロックするのが一般的で、別の POP 受信システムの受信と衝突する。INBOX 以外のフォルダ、フラグ照合（REQ-003）、移動検出が成り立たない | 0（実装量大） |
| D: 同期間隔を延ばす | 変更が設定値だけ | 干渉の頻度が下がるだけで、なくならない。新着反映の遅延が延びる | 微減 |

## 結果 (Consequences)

- 良い点: 同期ジョブがメールサーバに対して状態を変える操作を発行しなくなる。この保証はサーバではなくコード側にある。同期ジョブはフラグ変更・移動・APPEND を呼ばず、それをユニットテストで検証している。`EXAMINE` はサーバ側の防波堤にはならない。読み取り専用のフォルダからの COPY は禁止されず、imapflow は読み取り専用のフォルダへの STORE を例外にせず黙って捨てる（`PERMANENTFLAGS ()` を見て送らない、または NO を握りつぶして false を返す）。
- 悪い点 / トレードオフ:
  - Courier が `EXAMINE` でも新着状態を消費する実装だった場合、この変更では新着状態を守れない。ユーザ判断（2026-10-31）により、その場合は既知の制約として design.md に記録し、`EXAMINE` のまま運用する（選択肢 C は別の干渉を生むので採らない）。
  - MCP ツールの整理操作（既読化・フラグ・移動・ゴミ箱）は `SELECT` で開くので、対象の 1 通だけでなく、そのフォルダ内の全メッセージの新着状態を消費する。フラグの変更（STORE）は読み書きで開いたフォルダでしか効かず、MOVE 非対応サーバでの移動も `\Deleted` の付与（STORE）を伴うので、回避手段はない。整理操作はエージェントへの明示的な依頼で起きるので、許容する。予約送信の送信確認（Sent フォルダの検索）は読み取り専用でも動くが、ユーザ判断でスコープ外とし `SELECT` のまま残す。
  - dev と prod は同じメールボックスを同期している。両方のデプロイが済むまでは、もう一方の旧コードが新着状態を消費し続ける。実機確認は prod へのデプロイ後に行う。
- 憲法との関係: 準拠。
